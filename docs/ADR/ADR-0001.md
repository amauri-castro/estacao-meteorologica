ADR-0001 — Organização da arquitetura do backend

Contexto

O backend da estação meteorológica será desenvolvido como um
projeto solo de portfólio e estudo.

O sistema terá diferentes áreas de responsabilidade, como:

- dispositivos;
- ingestão de telemetria;
- observações;
- alertas;
- acesso.

Preciso definir uma estrutura que mantenha essas responsabilidades
organizadas sem introduzir complexidade desnecessária.

Alternativas consideradas

1. Camadas globais
   controllers/
   services/
   repositories/

2. Organização por módulo/funcionalidade
   dispositivos/
   ingestao/
   observacoes/
   alertas/
   acesso/

3. Microserviços

Decisão

Adotar um monólito organizado por módulos, com as camadas
controller, service e repository dentro de cada módulo.

Por enquanto, todos os módulos serão executados como uma única
aplicação Spring Boot.

Consequências

Positivas:
- responsabilidades ficam agrupadas por funcionalidade;
- facilita a navegação pelo código;
- mantém a aplicação simples de executar;
- permite evoluir os módulos sem introduzir microserviços.

Negativas:
- exige disciplina para evitar dependências indevidas entre módulos;
- algumas decisões de arquitetura poderão precisar ser revistas
  conforme o sistema evoluir.
